# 장소 씨앗 사건(SEED) 작업 지침

ONE PIECE LIFE의 "장소 씨앗 사건"을 이어서 넣기 위한 문서다. 사람이 쓰든 다른 AI(ChatGPT 등)가 쓰든 같은 기준을 따른다. 먼저 `CLAUDE.md` 전체(특히 2·4·5·6·8·9절)와 `docs/handoff/HANDOFF.md`를 읽는다.

## 1. 무엇인가

- 어떤 장소에서 자라는 아이(2~15세)가 겪는 어린 시절 선택 사건이다. 선택지는 3개(A/B/C)다.
- 고른 선택지마다 어른이 된 뒤(21~26세 무렵) **1차 회수** 장면이 돌아온다. 회수 장면의 선택지는 2개다.
- 회수 때 플레이어가 고향(씨앗 장소)에 살면 **고향 장면**이 나오고, 다른 곳에 살면 **타지 장면**(`back.away`)이 나온다. 타지 장면에서는 현장 행동 대신 편지·소포·방문객처럼 지금 사는 곳에서 할 수 있는 일을 한다.
- 원고는 사용자가 장소별 md 파일(`04_고아_왕국_중심가.md` 같은 형식)로 보내 준다. 원고 형식은 3절에 있다.

## 3. 원고 → 코드 변환 규칙

원고 한 편의 모양:

```
## SEED-04-01 | 고아 왕국 중심가: 구두 밑창 입장권 (11세)
상황: …(해라체)
- **A. 춤자국이 닳은 구두를 닦는다**
  - 즉시 결과: …
  - 1차 회수 (24세 · …): 상황 문장. X하면 Y. Z하면 W.
  - 타지 거주 시 같은 나이 · 현재 거주지: 상황 문장. P하거나 Q한다.
- **B. …** / **C. …**
발생 조건 및 구현 참고: …
```

변환 규칙 (**원고를 훼손하지 않는 것이 최우선**):

1. **문장은 끝맺음만 '~습니다'체로 바꾼다.** 내용·인물 이름·단어를 바꾸거나 줄이지 않는다. 명백한 오타만 고친다(예: "쥐인다"→"쥐여 준다"). 원고의 큰따옴표 대사는 두 개여도 그대로 둔다.
2. **제목·선택지 제목은 원고 그대로** 쓴다. 16자를 넘어도 줄이지 않는다.
3. `key`: `sd` + 장소 번호 2자리 + 편 번호 2자리 (SEED-04-01 → `sd0401`). 한 번 정하면 바꾸지 않는다.
4. `age`: 제목 괄호의 나이. `back.age`: 1차 회수 괄호의 나이.
5. `result`: '즉시 결과'를 ~습니다체로 옮긴다.
6. **1차 회수 분할:** 첫 문장(상황)은 `back.body`로, "X하면 Y. Z하면 W."는 선택지 2개로 나눈다. 선택지 제목은 "X한다"(행동, ~한다로 끝남), `result`는 Y.
7. **타지 분할:** 첫 문장(상황)은 `back.away.body`로, "P하거나 Q한다"는 선택지 2개(`P한다`, `Q한다`)로 나눈다. 원고에 결과가 없으면 타지 선택지에는 `result`를 쓰지 않는다(지어내지 않는다).
8. `back.title`: 원고에 회수 제목이 없으므로 회수 상황을 4~14자 명사구로 짓는다. 타지 장면은 `away.title`을 생략하면 고향 제목을 그대로 쓴다.
9. **원고에 없는 것만 새로 정한다:** `desc`(25자 이내 힌트, 숫자 없이), `effect` 수치, `log`(40자 이내, 명사형 ~함/~음/~됨), `memory`(20자 이내 명사구, 선택지 절반 정도에만).
10. '발생 조건 및 구현 참고'에 원작 연도 조건이 있으면 `when.minYear`/`when.maxYear`(해원력, `canonYear()`)로 건다. 회수에도 조건이 있으면 `back.when`에 건다. 연표 기준은 index.html의 `CANON_EVENTS`다(예: 그레이 터미널 화재 1512, 아론 점령 1512~1521, 아론 파크 붕괴 1522). 게임의 출생 연도는 1500~1506이다(`pickBirthYear()`).
11. 장소 이름은 index.html의 `places` 배열의 `name`과 정확히 같아야 한다(예: "고아 왕국 중심가", "코코야시 마을").

### 효과(effect) 기준

- 어린 시절 선택: 작은 효과(CLAUDE.md 2절 '소'). 돈은 수십 베리 이내. risk는 건강 -8까지.
- 회수 선택: 소~중. 돈은 ±5,000~60,000.
- **모든 선택지에 대가가 있어야 한다**(행복·건강·관계·명성·돈 중 하나가 마이너스). 모든 면에서 나은 선택지를 만들지 않는다(CLAUDE.md 8절).
- 쓸 수 있는 키: `health happiness knowledge relationship reputation combat money skills memory log` (+ `traits flags standing bounty`). `skills`는 검술·무투술·요리·의술·장사·제작·항해술만.
- 성향(traits)은 효과에서 자동 판정되므로 보통 적지 않는다.

## 4. 데이터 형식 (그대로 복사해 쓰기)

```js
/* ───────────── 09 고사 마을 ───────────── */
SEED("고사 마을", [
  {
    key: "sd0901", age: 12,                 // when: { minYear, maxYear } 필요하면 여기에
    title: "주소가 물 위로 떠올랐다",
    body: "뒤집힌 고사 마을의 잔해에서 문패가 떠오릅니다. …",
    choices: [
      { title: "집주인이 자주 가던 배로 간다", desc: "발품이 든다",
        result: "편지는 전 주인에게 온 것이었습니다. …",
        effect: { relationship: 3, health: -1, memory: "물 위로 뜬 문패", log: "문패의 주인을 찾아 배로 감" },
        // risk: { chance: 0.15, effect: { health: -3, log: "…" } },   // 선택
        back: {
          age: 24, title: "열쇠가 둘인 편지",
          body: "모은 편지를 찾아온 두 사람이 각각 집 열쇠를 가졌습니다.",
          choices: [
            { title: "봉투 이름대로 나눈다", desc: "…",
              result: "피난길에 갈라진 세입자와 주인이 각자 소식을 찾습니다.",
              effect: { …, log: "…" } },
            { title: "둘이 같이 열도록 기다린다", desc: "…",
              result: "…",
              effect: { …, log: "…" } },
          ],
          away: {
            body: "떠돌던 편지가 이곳의 같은 주소 두 집에 왔습니다.",
            choices: [
              { title: "이름대로 나눈다", desc: "…", effect: { …, log: "…" } },
              { title: "봉인을 확인하고 발신인 농담으로 가린다", desc: "…", effect: { …, log: "…" } },
            ],
          },
        } },
      // B, C도 같은 모양
    ],
  },
  // sd0902 … sd0906
]);
```

- 새 장소는 `seed-events.js` 맨 끝에 `SEED("장소", [...]);` 블록으로 이어 붙인다. 기존 01~08 블록이 실제 예시다.
- 파일 맨 위 주석에 원고 변환 원칙이 적혀 있다.

## 5. 엔진 동작 (바꿀 일이 있을 때만)

- 한 인생에 씨앗은 3개까지(`SEED_MAX_PER_LIFE`), 해마다 60% 확률(`SEED_YEAR_CHANCE`)로 그 장소에서 나이(age±1)가 맞는 씨앗 하나가 나온다. 같은 씨앗은 한 인생에 한 번.
- 고른 선택지는 플래그 `f_<key>_<a|b|c>`를 남기고, 회수는 그 플래그를 조건으로 `back.age-1 ~ back.age+2`에 나온다(회수 풀 `seed`, 해마다 70%). 한 번 나오면 다시 나오지 않는다.
- 회수 장면을 만든 뒤 보여 주기 전에 고향을 떠나거나 돌아오면 그 장면은 건너뛴다.
- 임펠다운 수감 중에는 씨앗 회수가 나오지 않는다.

## 6. 확인 방법 (자동 플레이 대신)

게임과 같은 출처에서 `docs/handoff/seedtest.html`을 열면 기본 경로의 `index.html`을 검사한다. 다른 게임 경로는 기존처럼 `#game=…`으로 지정한다. 테스트는 전용 브라우저 프로필에서 실행한다.

- 페이지가 실제 `seed-events.js`를 읽어 장소·키·선택·고향 및 타지 변형을 대조한다. 활성 씨앗의 세 선택을 각각 실행하고, 각 회수의 두 선택을 독립적인 상태에서 실행해 기록을 검사한다.
- 활성 399편 × 3개 선택 × 2곳 = 2,394장면이 합격 기준이다. 비활성 3편의 18가지 회수도 플래그를 주입해 차단을 확인한다. 게임 오류와 분기 오류 모두 0이어야 한다.
- 데이터 검사에서는 고대 장소를 포함해 연도와 출생 가정을 명시적으로 설정한다. 실제 출생 연도 1500~1506으로는 일부 옛 장소 씨앗에 도달할 수 없다. 고사 파괴 직후·오하라 및 플레반스 멸망 전·드레스로자 지배기 등의 연도 문턱을 상향 완화하지 않는다.
- Windows에서는 기존처럼 `tools/autoplay/lib.sh`의 `dump_pre`로 검사 페이지를 열 수 있다. 이 작업은 200판 자동 플레이 대신 위 검사 페이지를 사용한다.

## 7. 알려진 점

- `sd0802`(누가 제일 비싸요): 아론 점령기(1512~1521) 조건이라 1505·1506년생에게만 나온다. 회수는 1522년 이후.
- `sd0201`·`sd0204`: 그레이 터미널 대화재(1512) 전에만 나온다(`maxYear: 1511`).
- 원고 '발생 조건'의 세부(인물 생사, 봉쇄 시기, 버기 점령기 등)는 대부분 코드 조건으로 걸지 않았다. 알바나·유바의 원작 인물 카메오(SEED-24-02 비비, SEED-24-03 코자)는 원고에 "검증 전 비활성"이라 적혀 있으니 넣을 때 사용자에게 확인한다.
- 커밋·푸시는 사용자가 요청할 때만 한다. 답변은 한국어로 한다.

## 왜 만드나

팀의 요청: 지금 회수 사건은 한 번 돌아오고 끝나서 "거기서 고른 선택지가 반영이 안 되고 아무 일도 안 일어난다". 씨앗 이벤트가 **꼬리에 꼬리를 무는** 구조가 필요하다. 줄기는 고른 선택지가 다음 장면을 정하고, 그 장면이 또 다음을 부르는 3~4단계 이야기다. 같은 씨앗이라도 다른 선택을 하면 완전히 다른 이야기가 되어야 한다.

## 구조

```
1단계(갈림)  선택지 3개 → 각기 다른 2단계 노드
2단계(위기)  노드 2~3개, 같은 인물이 다른 모습으로. 선택지마다 next(또는 점수로 가르는 next)
3단계(결말)  end:true 노드 3~4개. 쌓인 선택이 정한 끝
(필요하면 2단계와 결말 사이에 단계를 하나 더 둔다. 노드는 줄기당 7~10개)
```

- 줄기마다 **이름 있는 인물 하나**가 처음부터 끝까지 나온다. 토큰 `{인물}`(조사는 `{인물|이}` `{인물|을}` `{인물|은}` `{인물|와}` `{인물|로}`).
- 선택은 스탯만이 아니라 **세상을 바꾼다**: 인물이 동료로 합류(`npcJoin`)·곁을 떠남(`npcLeave`)·원수/은인이 됨(`npcRole`)·소속/직업이 바뀜(`npcAff`·`npcJob`), 인연 변화(`npcRel`), 현상금·평판, 다음 장면이 오는 시기(`delay`).
- 결말은 쌓인 선택의 무게가 느껴지게. 좋은 선택만 보상받지 않는다(돌봐 준 인물이 짐이 되기도, 외면한 인물이 뜻밖에 돕기도).
- 신분이 바뀌었을 수 있다. 노드마다 `by`로 지금의 신분별 장면을 쓴다(최소 "해적|혁명군" / "해군" / "*"). 노드는 보여 주기 직전 신분이 만들 때와 같아야 나온다.

## 형식 (출력 파일에 그대로)

```js
ARC({
  id: "baker",                       // 영문 소문자
  name: "빵 도둑의 이야기",            // 화면: "🔁 빵 도둑의 이야기 · 2단계"
  start: [                           // 위에서부터 처음 맞는 규칙으로 시작
    { flags: ["f_cb_navy_kept_dream"], node: "s1", after: 6 },
    // 새 줄기: { when: { minAge: 17, maxAge: 26 }, chance: 0.08, node: "s0" } (해마다 8% 확률로 시작)
    // 동료 사건에서 이어받기: { flags: ["f_cbpick_cmp_w_secret_1"], node: "a1", after: 3, npcFrom: "cmp_w_secret" }
  ],
  nodes: {
    s1: {
      stage: 1,
      title: "…", body: "…",          // 6절 문체, 100~200자, {인물} 토큰
      choices: [                      // 2~3개
        { title: "…한다", desc: "…", next: "m_close", delay: [3, 5], score: 1,
          effect: { npc: { role: "동료", aff: "해군", job: "해군 신병" },   // 인물을 처음 만드는 노드에서만
                    relationship: 4, npcRel: 6, traits: { "선량": 1 }, npcStory: "…", log: "…" },
          risk: { chance: 0.3, effect: { … } } },
        …
      ],
      by: { "해적|혁명군": { body: "…", choices: [ { title, desc, effect, risk }, {}, … ] }, "해군": { … }, "*": {} }
    },
    m_close: { stage: 2, …, choices: [ { …, next: { ">=2": "e_bond", "else": "e_cold" } }, … ] },
    e_bond: { stage: 3, end: true, title: "…", body: "…", choices: [ … ] }   // 결말도 선택지 2개(어떻게 끝맺을지)
  }
});
```

### 엔진 규칙 (중요)
- `next`·`delay`·`score`는 **기본 choices에만** 적는다. `by`의 choices는 같은 자리(순서)의 기본 선택지에 덮어쓰기라 title/desc/effect/risk만 바꾼다. 그래서 **자리마다 뜻이 같아야 한다**(예: 1번=다가감, 2번=거리 둠, 3번=맞섬).
- `effect.npc: { role, aff, job, rel, title, near }`는 인물이 아직 없을 때만 만든다(줄기 첫 노드의 모든 선택지에 넣어 두면 안전). role은 "동료"(늘 곁에 다님)·"친구"·"은인"·"라이벌"·"원수" 중. aff는 "해군"/"해적"/"혁명군"/"민간인".
- `npcJoin: true` → 인물이 내 동료가 되어 곁에 다님(내 소속으로). `npcLeave: true` 또는 `"섬 이름"` → 곁을 떠남. `npcRole: "원수"` 등.
- `score`는 줄기 안에서 쌓인다. `next: { ">=2": "a", "<0": "b", "else": "c" }`처럼 가를 수 있다.
- 결말(`end: true`) 노드의 선택지는 next가 없어도 된다. 고르면 줄기가 닫힌다.
- 노드 사이 간격 `delay: [최소, 최대]`(기본 [2,5]). 인물의 나이·삶이 변할 만큼 둔다.
- `{동료}` 토큰은 쓰지 않는다(줄기 인물은 `{인물}`).
- 효과 수치: 갈림·위기는 '중', 결말은 '중~대'. 죽는 결과는 넣지 않는다. 모든 면에서 나은 선택지 금지, 효과 없는 선택지 금지, 선택지마다 traits 하나.

## 출력
지정한 파일 하나에 `ARC({...});`를 줄기 수만큼. 문법을 다시 확인한다(deno/cscript 가능). 끝나면 파일 경로, 줄기마다 노드 목록(노드 → 선택지별 next), 없애야 할 기존 2단계 사건 key(줄기가 대신하는 것)를 짧게 보고한다.
